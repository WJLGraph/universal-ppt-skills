# 质检门禁（Stage 5 按需加载）

> 第一版渲染几乎必有真实缺陷。质检不是走过场，是交付前最后一道闸。

## §0 硬门禁复诵（生成时跳过任何一条 = 返工；与 SKILL.md §0 十条铁律同源）

1. 视觉反模式清零（design-language.md §6：装饰线/色条/竖条纹/卡片单边描边含顶色条）
2. 论文 deck：**素材里已有的图必须用原文图**——`scripts/crop_paper_figs.py` 从 PDF 截原文（zoom ≥ 3）嵌入 + 每图 in-slide citation；**原文有图却不上片、或用自绘图/AI 图/图标/截图顶替原文图表 = 违规**；素材确实没有对应图才可自造，自造须是真实图片文件 + `figures.json` 登记 `source_type=self-made` 与 `reason` + 页内标「来源：自绘」
3. 每张嵌入图都在 `figures.json` 登记（pdf 页码 + Figure 号 + sha256），且台账登记的图片文件真实存在、哈希自洽；论文清单 `paper-figures.json` 里的每个 Figure 要么上片、要么在 `deck-spec.json` 的 `unused_figures_reason` 里有理由
4. 数字逐一与素材核对（记录表号/图号）
5. 讲稿 80–120 字：脚本逐页打印 `len()`，超限修剪
6. 程序化门禁有打印输出：`scripts/deck_qa.py` 原始输出必须贴出（下方 §1.5 清单）
7. 渲图目检背景色/清晰度/重叠，缺陷按 high/medium/low 分级
8. Action title 全覆盖（§1 第一条）

## §0.5 门禁脚本与人工检查的分工（先机器，后肉眼）

| 由 `scripts/deck_qa.py` 判死（G 级，不许人工"感觉没问题"） | 只能人工目检（脚本抓不到，必须渲图看） |
| --- | --- |
| 页数 / 讲稿字数 / 形状越界 / 文本溢出估算 | 文字是否被**视觉上**截断（估算不等于真实渲染） |
| 视觉页占比 ≥60%、连续非视觉页、视觉锚点 | 元素重叠、线条穿字、图片观感 |
| 禁语、占位符残留 | 对比度、对齐与间距、版式重复（slide-sorter 扫） |
| 图片来源哈希核对、台账文件存在性与自洽、in-slide citation 存在性 | 图表是否"裸奔"、配色是否廉价 |
| 两阶段确认门（outline_confirmed / style_confirmed） | 图片清晰度（渲图放大看） |
| action title 格式 | 论证链是否真的讲得通（ghost deck 人工读一遍） |
| **论文原图使用核查（G15：原图上片 / 未上片理由 / 自绘不得多于原图）** | **原文图裁得对不对（是否漏裁正文区、是否把表格当图裁）** |

**执行顺序**：先跑脚本修到全 PASS → 再渲图目检 → 修完复检一轮。两件事都做完才算 Stage 5 结束。

**视觉页严格定义（G5，堵住最常见的绕过）**：视觉页 = 该页含 **PICTURE / 原生图表 `has_chart` / 表格 `has_table`** 至少其一。文字框、色块、圆角卡片、纯形状拼的"示意图"**不计入**。判定以脚本输出为准，别用"这页看着挺丰富"自我说服。

## §2 视觉质检（渲染成图片逐页看）

优先级顺序（先修高级别）：

1. **文字溢出/截断**（最常见缺陷，永远用户可见）
2. 元素重叠（文字压形状、线条穿字）
3. 对齐与间距（同类元素未对齐、间距不均、块间 <0.3"、贴边 <0.5"）
4. 对比度（浅字浅底/深字深底，图标无对比底）
5. 版式重复（连续三页同一版式；slide-sorter 扫描 5 页以上同构图）
6. 图表裸奔（无标题/无标签/默认配色）
7. AI 味反模式（对照 design-language.md §6 逐项扫）
8. 中文去模板化短语（对照 design-language.md §7 清单扫）

**严重度分级**（提炼自 nature-paper2ppt）：

- **high（阻断交付）**：证据被裁切（坐标轴/图例/panel 标签/表格行）、关键结果页主证据不可读、文字溢出或被裁、页序错乱或缺核心证据、编造的量化表述
- **medium**：过密页、AI 模板味版式（重复等分卡片/清一色右轨/装饰指标行）、裁切边缘过紧、图注脱离视觉、讲稿缺失或无用、来源归属含糊
- **low**：轻微对齐瑕疵、色板/字体微调、可读但密图未拆

处理规则：high 全修；medium 修掉不显著扩大工作量的；low 记录可不修。修完重渲复查，连续一轮无新缺陷即停（不无限打磨）。

**程序化检查清单**（**已固化为脚本，出片后先跑它，别手抄手算**）：

```bash
python scripts/deck_qa.py <deck.pptx> --spec work/deck-spec.json --figures work/figures.json \
       --paper-figures work/paper-figures.json --mode A --out work/qa_output.txt
```

脚本覆盖：G1 页数 · G2 讲稿字数逐页打印 · G3 形状越界/巨型形状 · G4 文本溢出估算 · G5 视觉页占比（严格定义见 §0.5）· G6 连续非视觉页 · G7 视觉锚点 · G8 占位符扫描 · G9 禁语扫描 · G10 图片来源哈希核对 + 台账文件存在性/自洽 + 学术模式图源合规 · G11 in-slide citation · G12 两阶段确认门 · G13 action title · G14 字族与默认阴影统计 · **G15 论文原图使用核查（原图上片 / 未上片理由 / 自绘不得多于原图）**。FAIL 非零即不许交付。

仍需人工补做的项（脚本抓不到，必须渲图/放大看）：

- 真实渲染下的文字截断（估算 ≠ 渲染）、元素重叠、线条穿字
- 近似对齐（同类元素边缘差几像素）、间距不均、贴边 <0.5"
- 对比度（浅字浅底/深字深底）
- 版式重复：slide-sorter 缩略图扫一遍，5 页以上同构图必须重构其中部分页面
- 图表裸奔：无标题/无标签/默认配色
- 图片清晰度（把证据图放大看，确认坐标轴/图例/panel 标签/表格行未被裁）
- 画布底色核验：渲图角落像素 + 背景 XML 双确认后再下结论（预览缩放的观感可能误导，白色底常被看成灰）
- 主证据图过小（低于页面 1/4 需人工确认）

**渲染预览政策**：渲图流程（LibreOffice→PDF→pdftoppm→逐页看图）；修改后必须从改过的 PPTX 重新走完整转换链，不能复用旧图。无可靠渲染器的环境降级为：程序化检查 + 资产裁剪拼图检查 + 逐页文本/形状审查，并在交付说明中注明"渲染预览不可用"。

图像式 PPT（R3/R4）追加：图像内文字是否幻觉/错字（不可编辑，只能重生成）；页面编号/水印是否意外出现。R8 追加：重建页与原图并排对比（contact sheet），结构无遗漏、无新增幻觉元素、箭头/公式为原生对象。

字体注意：QA 渲染器的字体替换与真实打开环境不同——用安全字体（Calibri/Arial/微软雅黑等）做容器宽度计算，非安全字体留 10% 宽度余量（安全清单见 design-language.md §2）。
